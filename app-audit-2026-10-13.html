Editing a house-made formula can't see its own price
Safe to fix now
What happens
On a formula's edit form, a supplier row set to In house is meant to show that formula's current cost per gram. The code that works that out is asking "which herb am I editing?", but the answer lives in a different part of the file that it can't reach. So it always thinks the form is for a brand-new herb and shows a blank price. It fails quietly. There's no error message.
You'd notice
Open an existing formula, add or keep an In house row: the $/g comparison for that row is empty instead of the real cost.
Where
index.html:23873 reads it · index.html:40952 is where it's actually kept (inside renderPharmacy)
Fix
Move that one value to a place both spots can see. Two or three lines. I traced this in the code; I haven't clicked through it on a real formula.

5
About 28 animations ignore the "reduce motion" setting
Safe to fix now
What it is
Phones and computers have a "reduce motion" setting for people who find movement uncomfortable. The app respects it on most pages (70 rules do), but an estimated 28 of about 190 animated bits don't.
Examples
Herb form sliding in, stocktake card, the update spinner, To Order row glow, plan-table rows rising in, the Dispense ingredient rows (new, shake, rise), the "flow step" pops, and the "saved" fade.
You'd notice
Nothing, unless that setting is on. This is a rough count and a lower bound: I matched animations to their switch-off rules by name, so a few may be covered in a way I missed.
Fix
Add the missing switch-offs next to each animation. No visible change when the setting is off.

Two different "make text safe" helpers, and the main one is less careful
When you say
What it is
Anything a patient or you type goes through a helper called esc before it is shown. The main copy (used 3,361 times) turns an empty value into the actual words "null" or "undefined", and doesn't handle apostrophes. Is it unsafe?
No, not today. I checked that nothing puts it inside a single-quoted attribute, which is the only place the apostrophe gap would matter. The empty-value case would just show a stray word if some field was ever missing.
Where

Fix
Make the main one empty-safe like the second. One line, but it touches how every screen prints text, so I'd run the full page sweep after.
